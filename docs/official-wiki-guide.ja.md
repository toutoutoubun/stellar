> 作成日: 2026-05-11

このドキュメントは、Stellar の公式Wikiを作成・整備するときに必要な情報、推奨ページ構成、執筆Tips、公開前チェックリストをまとめたものです。

## 1. Wiki全体の目的

Stellar の公式Wikiは、README よりも実用寄りに、ユーザーが「導入する」「使い始める」「困ったときに解決する」「開発に参加する」ための情報を整理する場所にします。

README はプロジェクトの入口、Wiki は継続的な利用と学習の拠点として役割を分けます。

### 主な読者

| 読者 | 知りたいこと |
|---|---|
| 初めて使う人 | Stellar が何をするアプリか、どうインストールするか、最初に何をすればよいか |
| 高校生・大学生 | 論文管理、ノート、レポート執筆、探究活動での使い方 |
| 研究者 | 文献管理、引用ネットワーク、質的分析、量的分析、データ保全の仕様 |
| 開発者・翻訳協力者 | 開発環境、コントリビュート方針、翻訳追加、プラグイン作成方法 |

### Wikiのトーン

- 静かで実用的に書く。
- 「AIで自動化」「一緒に伴走」のような表現は避ける。
- ユーザーの判断、ローカルファースト、データ所有権を尊重する。
- 高校生でも読める平易さを保ちつつ、研究者向けの正確さも残す。

## 5. ページ別に載せるべき情報

### インストールと初回セットアップ

必須項目:

- GitHub Releases からダウンロードすること。
- macOS は `.dmg`、Windows は `.msi`、Linux は `.AppImage` を案内すること。
- 初回起動時は5ステップのオンボーディングがあること。
- 言語、保存先、テーマはあとから設定画面で変更できること。

注意:

- README では macOS 11以降、`tauri.conf.json` では `minimumSystemVersion: 10.15` になっている。公開前にサポート対象を統一する。

### クイックスタート

おすすめの流れ:

1. ライブラリで論文を追加する。
2. PDFを添付する。
3. PDFを読んでハイライトする。
4. ハイライトにコメントを付ける。
5. ハイライトからノートを作る。
6. ノート内で `[[ノート名]]` や `[[論文タイトル]]` を使ってつなげる。
7. グラフビューで関係を見る。
8. 必要に応じて草稿モードやエクスポートを使う。

Tip:

- 最初から質的分析・量的分析を全部説明しない。基本は「ライブラリ + ノート + グラフ」から始めると理解しやすい。

### 文献ライブラリ

必須項目:

- 論文・書籍・資料を管理できること。
- 追加方法は PDF / URL / DOI / 手入力 / ブラウザ拡張。
- タグ、検索、発行年、PDF有無などで絞り込めること。
- 読書ステータスは未読・読書中・完了・再読。
- 詳細パネルにメタデータ、ハイライト、関連ノート、引用ネットワークを表示できること。

### PDFリーダーとハイライト

必須項目:

- PDF表示、ズーム、ページ移動、検索に対応。
- 4色のハイライトを使えること。
- ハイライトにコメントを付けられること。
- 選択したハイライトからノートを作成できること。

Tip:

- 色の使い分け例を載せると初心者が使い始めやすい。
- 例: 黄色=重要、緑=方法論、青=自分の論点、赤=疑問点。

### ノートとWikiLink

必須項目:

- Markdown エディタであること。
- `[[ノート名]]` と `[[論文タイトル]]` による WikiLink に対応すること。
- `[[` 入力時にオートコンプリートが出ること。
- バックリンク、アウトライン、自動保存、フォーカスモードを説明すること。

Tip:

- WikiLink は「あとから整理する」ためではなく、「書きながらつなげる」機能として説明すると伝わりやすい。

### 草稿モードと引用

必須項目:

- 長文執筆用のモードであること。
- 章の追加・削除・並び替え・折りたたみができること。
- ライブラリの論文をインライン引用として挿入できること。
- APA 7th / MLA 9th / Chicago 17th / 一橋スタイルに対応すること。
- 参考文献リストを生成できること。

### ナレッジグラフと引用ネットワーク

必須項目:

- ナレッジグラフは論文とノートの関係を可視化すること。
- ノードクリック、ホバー、ダブルクリック、ズーム、パンを説明すること。
- 引用ネットワークは外部学術APIから引用・被引用関係を取得すること。
- CrossRef、OpenAlex、Semantic Scholar の用途を整理すること。
- 関連論文レコメンデーションとワンクリックインポートを説明すること。

注意:

- 外部APIが必要な機能は、オフラインでは制限される可能性があることを明記する。

### 質的分析

必須項目:

- 人文・社会科学向けの質的分析ツール群であること。
- 11タブ構成を一覧で示すこと。

載せるタブ:

| タブ | 説明 |
|---|---|
| ダッシュボード | プロジェクト概要、集計 |
| コードブック | 階層型コード管理 |
| コーディングマトリクス | コード x 論文の集計 |
| ICR | Cohen's Kappa、一致率 |
| 史料批判シート | 著者、年代、真正性、バイアス、信頼性 |
| タイムライン | 事象を時系列で整理 |
| アクターマップ | 国家・組織・個人などの関係可視化 |
| プロセストレーシング | 因果仮説と証拠の検証 |
| 比較分析 | MSSD / MDSD、ケース x 変数 |
| フレーミング分析 | Entman の4要素 |
| レポート | 分析結果の出力 |

Tip:

- 初心者向けページでは「質的分析とは何か」から始める。
- 研究者向けページでは、分析手法名と出力できるものを先に示す。

### 量的分析 Data Studio

必須項目:

- CSVを取り込んで簡易統計分析ができること。
- 変数型は scale / nominal / ordinal / text / date。
- 分析ウィザードは「手法選択 → 変数指定 → 結果表示」の3ステップ。
- 記述統計、頻度表、相関分析、t検定、カイ二乗検定、線形回帰に対応すること。
- トークン頻度、TF-IDF、チャート出力に対応すること。

### エクスポートと研究パッケージ

必須項目:

- ノートは PDF / DOCX / 静的サイトに出力できること。
- 全データの JSON エクスポートがあること。
- `.stellar` 研究パッケージで論文、ノート、ハイライト、リンク、PDFをまとめられること。
- BibTeX / RIS エクスポートに対応すること。

研究パッケージの構造:

```text
package.stellar
├── manifest.json
├── papers.json
├── notes.json
├── highlights.json
├── links.json
└── pdfs/
```

### クラウドバックアップとセキュリティ

必須項目:

- バックアップはユーザーのPC上で暗号化されること。
- 暗号化方式は AES-256-GCM。
- 復元には12桁のリカバリーコードを使うこと。
- サーバーには暗号文のみが保存され、復号鍵はクライアント側にあること。
- オフライン時は `~/.stellar/cloud_backups/` に暗号化済みバックアップが保存されること。

必ず強調する注意:

- リカバリーコードを失うと、新しいPCでクラウドバックアップを復元できない。
- 設定済みPCが手元にある間に、紙・パスワード管理ツール・安全なメモなどに保管する。

### ブラウザ連携 Stellar Clipper

必須項目:

- Stellar は `127.0.0.1:57321` でローカルHTTPサーバーを起動すること。
- ブラウザ拡張から論文メタデータを `POST /api/import` で取り込むこと。
- デスクトップアプリが起動していないと拡張機能は接続できないこと。

### 設定とカスタマイズ

必須項目:

- テーマは White / Ivory / Dark Blue / Black。
- フォントサイズ、行高さ、エディタフォントを変更できること。
- 保存先、エクスポート、バックアップ、研究パッケージ、ブラウザ連携、クラウドバックアップはデータタブにあること。
- 言語は日本語 / English / Francais / Afrikaans。

### 開発者向けセットアップ

必須項目:

- Node.js 22以降。
- Rust 1.75以降。
- Tauri CLI。
- 開発コマンドは `npm run tauri dev`。
- フロントエンドは React 19、デスクトップは Tauri 2.0、バックエンドは Rust、DBは SQLite。

基本コマンド:

```bash
npm install
npm run tauri dev
npm run tauri build
npm run lint
```

注意:

- `package.json` ではパッケージマネージャとして pnpm の設定がある一方、README/CONTRIBUTING には npm コマンドがある。公式Wiki公開前に `npm` と `pnpm` の推奨を統一する。

### アドオン・プラグイン作成

必須項目:

- リポジトリ内ローカルアドオンの入口は `src/plugins/registerAnalysisAddons.ts`。
- 質的分析タブ追加と量的分析手法追加の2系統があること。
- 配布用プラグインは `stellar-plugin.json` と `index.js` を含むフォルダ、または `.zip` / `.stellar-plugin`。
- プラグインIDは安定した英数字・ハイフンにすること。

注意:

- プラグイン機能は実装状況と公開状態を確認してからWikiに載せる。

## 7. FAQに入れるべき質問

| 質問 | 回答の要点 |
|---|---|
| PDFからタイトルが取れない | PDFメタデータが不十分な場合がある。手動修正が確実 |
| 自動保存が不安 | ステータスバーの「保存済み」を確認 |
| グラフに何も出ない | WikiLink、論文紐づけ、フィルタ設定を確認 |
| データ消失が心配 | クラウドバックアップ、自動バックアップ、ローカルバックアップ、研究パッケージを案内 |
| リカバリーコードを失くした | 設定済みPCから確認可能。PC故障後は復元不可 |
| クラウドバックアップは安全か | AES-256-GCM、E2E暗号化、サーバーは復号不可 |
| オフライン時のバックアップ | 暗号化済みファイルをローカル保存 |
| 言語変更が一部反映されない | アプリ再起動を案内 |
| Stellar Clipperが待機中 | デスクトップアプリ起動、拡張機能、設定画面の手順を確認 |
| 分析機能が難しい | 最初はライブラリ、ノート、グラフだけで十分と案内 |

## 8. 執筆Tips

### READMEとWikiの役割を分ける

- README: 魅力、思想、ダウンロード、概要。
- Wiki: 具体的な操作、FAQ、仕様、開発手順。

同じ文章を丸ごとコピーすると更新漏れが起きやすいので、Wikiでは手順と補足に寄せます。

### 1ページ1目的にする

1ページに複数機能を詰め込みすぎないようにします。たとえば「ノート」「草稿モード」「引用」は近い機能ですが、ユーザーの目的が違うため別ページに分けると探しやすくなります。

### 最初の3行で結論を書く

各ページ冒頭は、次の型にすると読みやすいです。

```md
# 文献ライブラリ

文献ライブラリは、論文・書籍・資料を一か所に集めて管理する画面です。
PDF、URL、DOI、手入力、ブラウザ拡張から文献を追加できます。
検索、タグ、読書ステータスを使うと、研究プロジェクトごとに資料を整理できます。
```

### 注意書きは短く強く書く

クラウドバックアップのリカバリーコードなど、失敗時の影響が大きいものは目立たせます。

```md
> 重要: リカバリーコードを失うと、新しいPCでクラウドバックアップを復元できません。
```

### 画面説明は「場所 → 操作 → 結果」の順にする

例:

```md
設定画面の「データ」タブを開きます。
「今すぐバックアップ」を押します。
バックアップが完了すると、履歴一覧に新しい項目が追加されます。
```

### スクリーンショットを入れる場所

スクリーンショットは以下に優先して入れると効果的です。

1. Home: アプリ全体画面
2. クイックスタート: ライブラリ、PDFリーダー、ノート、グラフ
3. クラウドバックアップ: リカバリーコード表示部分
4. 質的分析: コードブックまたはコーディングマトリクス
5. 量的分析: 分析結果とチャート

ファイル名例:

```text
images/wiki/home-main-window.png
images/wiki/library-add-paper.png
images/wiki/pdf-highlights.png
images/wiki/notes-wikilink.png
images/wiki/graph-view.png
images/wiki/cloud-backup.png
```

### 避ける表現

| 避ける表現 | 理由 |
|---|---|
| AIが研究を支援します | Stellar は AI 非依存が設計思想 |
| あなたに伴走します | プロジェクトの思想と合わない |
| すべて自動で解決します | 研究者自身の判断を尊重する設計と矛盾 |
| 完全に安全です | セキュリティ説明では脅威モデルと限界も必要 |
| どんな研究にも最適です | 対象は主に人文・社会科学 |

## 10. 更新運用Tips

- リリースごとに `FEATURES.md` とWikiの差分を確認する。
- UI文言を変更したら、対応するWikiの手順も確認する。
- 新機能は README に短く、Wiki に詳しく書く。
- 仕様ページは「実装済み」と「計画中」を混ぜない。
- 画像は機能名と画面名が分かるファイル名にする。
- FAQはIssueで多い質問から追加する。
- 翻訳Wikiを作る場合は、まず日本語版を安定させてから英語版に展開する。

## 11. 最初に作るならこの5ページ

公式Wikiを一気に全ページ作るのが大変な場合は、以下の5ページから始めるのがおすすめです。

1. `Home`
2. `インストールと初回セットアップ`
3. `クイックスタート`
4. `FAQとトラブルシューティング`
5. `クラウドバックアップとセキュリティ`

この5つがあれば、初めてのユーザーが導入し、基本操作を試し、データ保全の不安を解消できます。その後、機能別ページと開発者向けページを増やすと運用しやすくなります。
